This PR modifies tensor initialization in a specific fusion optimization pass (`AllreduceRMSNormFusion`), changing `torch.empty_like(input)` to `torch.zeros_like(input)` in the residual tensor initialization. This affects how the fused AllReduce + RMSNorm operation initializes memory, which could impact numerical correctness and tensor contents. Based on the diff, I'm keeping only tests that directly exercise the AllReduce + RMSNorm fusion path or would catch numerical regressions, dropping the hundreds of unrelated tests from the candidate set (lora, quantization, multimodal, etc. that don't specifically test this fusion).

---
tests/compile/fusions_e2e/test_tp2_ar_rms.py | directly tests AllReduce + RMSNorm fusion
tests/compile/passes/distributed/test_fusion_all_reduce.py | tests AllReduce fusion pass
tests/basic_correctness/test_basic_correctness.py | catches numerical correctness regressions
